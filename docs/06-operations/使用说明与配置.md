## 使用说明

- **评审**：`runner.py --repo <仓库> --range A..B`；产出报告过
  `report-check.py`（七段模板）与 `schema-check.py` 双闸；行内评论包经
  `pr-kit.py` → `pr-publish.py`（只创建 PR 不合并）。
- **修复**：评审发现 → 审核人闸 1（`approve-plan.py` 签工单）→ 修复团队
  （`fix-patch.py` 只吃工单）→ 审核人闸 2（`approve-patch.py` 五项核验签
  批准书）→ `fix-apply.py --apply` 过五道闸落盘（confirm 语义见 MCP
  `code_review_apply`）。
- **复盘**：每轮末尾 `retro-ledger.py`（事件 + 产物痕迹去重入台账）→
  `retro-report.py`（轮报 + 机器候选清单）；每轮开局先读
  `retro/next-round.md`——人工维护的检查单，report 不写它（round-28 根治）。
- **SWE-bench 单实例**：`agent/swe_run.py prepare/build/eval/report` 四阶段；
  镜像获取纪律与实测路线见 `agent/swe-workflow.md`。
- **镜像源判定**：`python scripts/docker-mirror-probe.py --image <owner/repo>`
  （硬约束 8：任何镜像下载前必须先跑，blob 段实测速度才算数）。

## MCP 工具描述规范（AB-09，r196）

> 依据：SWE-agent ACI 研究（接口设计决定 agent 成功率）+ FastMCP 生态共识
> （工具描述=提示注入面+提示工程）。r195 ACI 审计表：`reports/aci-audit-r195.md`。

1. **描述即契约**：每个 MCP 工具的 description 必须显式标注——功能、入参语义、
   返回形态、**副作用**（只读/写经验库/写被审仓库）、退出码语义（0/1/2 与
   NEED_HUMAN/WAIT_HOST_LLM 等特殊码）。annotations 的 readOnlyHint/
   destructiveHint 必须与描述一致。
2. **写类工具必须挂闸**：写被审仓库的工具（apply/fix）描述中必须写明闸面
   条件（apply=confirm=true+批准书 sha256+自动回滚；fix=只吃工单+只写产物
   目录）；条件必填参数在 schema 无法表达时，描述中必须写清失败语义
   （如 scan 的 path/diff_path 互斥 → rc=2）。
3. **mcp-scan 护栏流程**：工具描述=提示注入面——nightly 每次
   `npx -y mcp-scan@2.3.0 scan`（self-check.yml，critical/high 判红）；
   首次 CI 报告落 `reports/mcp-scan/baseline.json`，后续 nightly diff 对账，
   baseline 变更须经评审（描述改动=提示面变更）。
4. **ACI 三准则**：新工具设计时对照「短命令（参数面最小化）/ 反馈及时
   （错误即返+退出码语义）/ 防呆（条件必填显式+危险面拦截）」
   （SWE-agent ACI 研究， reports/absorb-list-r194.md AB-07）。



## 配置说明

- **运行参数**：`agent.json` args（超时、预算、轮数、评测配置）；脚本经
  `manifest_args.py` 真读，未显式传 `--config/--agent-json` 时按
  「CWD → 项目根」定位。
- **LLM 接入（可选，缺失自动降级为纯确定性评审）**：

```bash
# OpenAI 兼容端点
export REVIEW_LLM_BASE_URL=https://<端点>/v1
export REVIEW_LLM_API_KEY=<密钥>
export REVIEW_LLM_MODEL=<模型名>

# 或桌面宿主模型协议（零 API key，会话内推荐）
export CRA_LLM_PROVIDER=host
```

  未配置时评审以确定性规则照常运行（WAIT_HOST_LLM 语义与降级规则见
  `BASELINE.md`「LLM 提供者契约」）。
