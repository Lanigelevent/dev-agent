## 详细摘抄

v1.11/v1.12 的 run-samples.py 用正向 diff（git diff parent fix），而扫描器只看 + 行=修复后代码；taint-cross 更是直接扫 HEAD 工作区（=修复后状态）。后果双杀：①缺陷态的规则形态全部漏报（recall 虚低）②修复新增的形态被误记为抓住 bug（requests 的 pickle 命中即伪影，precision 虚高）。实证：该样本正向 diff + 行含 pickle.loads 而 - 行不含。修正：反向 diff（git diff fix parent，与 prepare 的 git show -R 同口径）+ 父版本 git worktree 供跨文件引擎；修正后 requests 命中消失、paramiko 命中变为真命中（缺陷态测试里的真实凭据形态）。

## 教训与对策

测量工具必须先有『测量对象是什么』的方向契约测试（构造缺陷态带已知形态、修复态干净的样本，红→绿）；发布任何指标前先自证方向；新脚本接入链路时逐参数核对既有环节的方法论（prepare 用 -R 我却用了正向）。
