## 为什么这样重构

访客信任不完全来自说"我们有什么"，而来自三件事：**能否不查就起走、硬约束是什么、不承诺什么。**
旧 README 在这三件事上都回答得不好：使用路径藏在目录树里、限制见 SLA 口径、uncovered 东西半删半藏。
重构后：

1. 第一屏先读**能力边界**（先告诉它不做什么）与关键事实表；
2. 三条阅读路由匹配三种读者——使用者/改代码/评估者；
3. 逐版沿革显式指针到 PROGRESS.md/BASELINE-HISTORY.md，不指"本页"存真值；
4. 门禁边界（四类未验证）以表格形式列出，附单独核验法——等同于自动化报告生成系统 README 里「仍未被默认入口覆盖的是 4 处」的明示块；
5. 排障速查照着本月本轮的真实踩坑写，不是装饰。

## 代价与回退

- **回退不了的记忆**：本 README 仍不得作为逐版 release notes；CHANGELOG/PROGRESS 仍是逐版真值权威。
- **门禁**：本页改参数（future-proof 不可能）也需要先跑 `round-gate`，再过 `release-gate`；本轮全部一次过。
- **评审口径**：README 重构不改变代码行为，精度/口径/台账不变；只做了展示与护栏。
