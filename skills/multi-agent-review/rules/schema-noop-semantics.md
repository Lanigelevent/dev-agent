# 规则：schema/迁移操作的空操作语义

**适用**：数据库迁移、schema 操作（重命名、改表选项、加约束）、幂等部署
脚本——`**/migrations/**` 与 `**/models.py` 命中本规则。

**判据**：当目标状态已经满足时，schema 操作必须是**真正的空操作**：
不产生副作用、不报错、不写多余记录。把"已满足"当错误处理，或重复执行
已完成的变更，都是缺陷。

**反例形态**：`RenameModel` 在 `db_table` 已指向新名时仍生成并执行重命名
SQL——对已迁移环境这是空操作场景，却产生了重复/报错副作用。

**评审动作**：对迁移类 diff，逐一问"这个操作在已完成/部分完成/全新三种
起始状态下分别做什么？"——三种里有一种产生非预期副作用就驳回。

出处：SWE-bench 实例 django__django-14999（round-33：补丁只修了
RenameModel 一个面向，db_table noop 语义层漏网）。
